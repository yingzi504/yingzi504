# 📝 API重构方案

## 🤔 当前问题

### 现状
```
/fill          → 原始填充
/fill/smart    → 智能填充（推荐）
/fill/advanced → 高级填充（实验性）
```

### 问题
- 三个接口功能类似，用户困惑
- 接口命名不直观
- 缺少统一的入口

---

## ✅ 重构方案

### 方案A：单一智能接口（推荐）

**端点**:
```
POST /fill          → 使用智能填充（推荐）
POST /fill/legacy   → 保留原始版本（向后兼容）
```

**优点**:
- 简洁明了
- 默认使用最佳实现
- 保留向后兼容

---

### 方案B：带模式参数的接口

**端点**:
```
POST /fill
{
  "mode": "smart" | "legacy" | "advanced",
  ...
}
```

**优点**:
- 完全统一
- 灵活性高

---

## 🎯 推荐实施方案（方案A）

### 步骤
1. 让 `/fill` 使用智能填充
2. 添加 `/fill/legacy` 保留原始版本
3. 移除 `/fill/smart` 和 `/fill/advanced`

### 迁移指南
- 新用户: 使用 `/fill`
- 旧用户: 迁移到 `/fill` 或使用 `/fill/legacy`
