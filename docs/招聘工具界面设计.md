## 页面与交互

1. 页头：候选人 CDD、负责人 PE、职位 Title、预计入职日期；沿用 #954DFF 系统主题。
2. 薪资方案：当前薪资作为涨幅基准，初始三份空白报价，支持新增、复制、移除及重命名。固定左侧项目列与顶部报价名，底部固定年包/涨幅结果区，内部滚动；白色输入与灰色只读单元格并排显示。
3. 社保确认：选择报价与缴纳地，查看各险种的基数、个人/企业比例及月金额。默认新员工工资与报价月薪联动；老员工可填上年度月平均工资。
4. Hourly / Daily Rate：选择多个城市，将各报价放在同一表内比较。包含公司月缴费、不含 Overhead 成本、含 Overhead 成本；切换小时/天。
5. 固定规则：只读展示发薪月数、年终奖倍数、工时、Overhead、五地上下限及公式说明。
6. “载入原表示例”填入 B12:E18 的示例，不代表真实候选人；明确提示覆盖后可清空。默认不预填敏感薪资。

### 计算顺序与精度

- 先按对应险种下限/上限限定基数。上海基数再 ROUND(...,0)，其他城市保留原工资小数。
- 个人养老、医疗、失业：ROUNDUP(基数 × 比例,1)。
- 公司养老、医疗、失业、生育、工伤：ROUND(基数 × 比例,2)。
- 个人/公司公积金：ROUND(公积金基数 × 比例,0)。
- 公司补充公积金：ROUND(公积金基数 × 补充比例,0)，不再乘 2。
- 合计逐项取整后相加。代码使用整数分和基点计算缴费，避免浮点误差导致 ROUNDUP 多收 0.1 元。
- 年包 = 月薪 × 12 + 驻场津贴 + 年终奖 + 项目奖金 + 年度福利 + 年包补充公积金。
- 涨幅 = ROUND((报价年包 − 当前年包) / 当前年包,2)。保留原表对比率本身取两位小数的行为，例如原表示例报价 1 显示 5.00%，不改成未取整的 4.60%。分母为 0 时不计算。
- 不含 Overhead Hourly Rate = (年包 − 上海年包已含补充公积金 + 公司月缴费 × 12) / 1,880。
- 含 Overhead Hourly Rate = (年包 − 上海年包已含补充公积金 + 公司月缴费 × 12 + 169,200) / 1,880。
- Daily Rate = 未取整的 Hourly Rate × 8。最终展示两位小数，中间 Hourly Rate 不提前取整。

## 已确认差异与保留事项

### SAL-001：北京原表引用差异（已按用户确认修正）

原 C26 为 `($C$19+$AM$5*12)/1880`，D26/E26 同样引用 AM5（合肥）；北京实际成本为 AM4。用户明确确认“改为北京成本，并记录与原表的差异”。网页含/不含 Overhead 都使用北京成本。

原样例报价 1：不含 Overhead 从 208.063829787234 改为 211.382978723404 元/小时，界面显示 211.38。

### SAL-002：报价工资与社保联动（已实现）

原表 B3:B7 都为 20,000，所有报价共同引用各城市 AM 列，因此 25,000 / 30,000 的报价仍沿用 20,000 对应成本。F12 提示需手动保持一致。网页每份报价自动按自己的工资计算，防止漏改；这会令后两份报价的成本与原表缓存不同。支持老员工上年平均工资独立输入。

### SAL-003：上海补充公积金去重（已按用户确认修复）

用户确认上海存在重复计费，要求重新核对部署。原 AL3 = ROUND(I3 × 8%,0) × 2，同时 C18 又有年包补充公积金，造成实际三份计入。

- 公司缴费明细取消 × 2，只计 ROUND(公积金基数 × 8%,0)。普通公积金 7% 保留。
- 候选人年包保持原展示。上海企业成本 = 年包 − 手填年包补充公积金 + 实际公司月缴费 × 12。
- 以实际缴费为成本唯一来源，避免工资封顶、老员工基数、取整及手填金额不相等时仍重复计入。不使用 min(年包值,缴费值) 等会遗留重复金额的算法。
- 白色手填年包补充金额为 0 时仍计算实际公司缴费；空白时相关成本结果待填。其他城市现有规则保持不变。
- 原表示例月薪 20,000、年包 305,000、年包补充 19,200：公司补充 3,200 → 1,600 元/月；公司月缴费 10,192 → 8,592；企业年成本 427,304 → 388,904（不含 Overhead）。
- Hourly Rate：227.29 → 206.86（不含 Overhead），317.29 → 296.86（含 Overhead）；Daily Rate 为 1,654.91 / 2,374.91。

### SAL-004：福利与年包补充公积金（保留手填）

原 C17:E17 为共享公式 `1800+1100+1100+1200+600`，但没有各福利项名称或性别/销售电话费映射。原 C18 带公式，D18/E18 为 0，均为白色手填区。网页不据此推断固定福利或城市自动金额。页面提示切换城市后重新核对，这些年包项不会随城市自动重写。
